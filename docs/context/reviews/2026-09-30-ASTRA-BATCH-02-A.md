## CSBOMB v0.1 — 판정: pass
치명 문제: 없음.
- 종료: 라운드는 숨은 도화선(15~35초)으로 반드시 끝나고 5라운드 고정. 무응답·오답 반복으로 멈추지 않는다. 초성 답 고갈 시 초성만 새로 뽑는 처리 있음(52·58행).
- 비밀: 도화선 값은 view·재접속·알림 어디에도 보내지 않고 폭발 뒤 공개(32·71행).
- 3명: 전달 대상 2명 중 무작위로 성립. 소지자 이탈 확정 시 폭사 기록 후 라운드 종료(70행).
- 입력: 전용 입력칸(text) — 플랫폼 가능.

비치명 메모:
- 소지자 외 활성 참가자가 0명일 때(진행 중 라운드에 두 명 이탈 확정) 정답 제출의 전달 대상이 정의되지 않음 → 도화선으로 라운드는 끝나므로 치명 아님. “대상 없으면 소지 유지” 한 줄 필요.
- 초성 조합 조건이 31행 “답 40개 이상”과 45행 “안 쓴 답 ≥ 40개”로 표현이 다름 — 구현 때 하나로.
- 전달 대상에 재접속 유예 중(미확정) 참가자를 포함하는지 명시 없음 — 09-4절상 포함으로 해석.

## CLAP v0.1 — 판정: pass
치명 문제: 없음.
- 종료: 차례 시간 4→2초 초과 시 탈락, 생존자 1명이면 종료, 안전 상한 6분(40·42행). 차례인 사람의 유예 중 이탈도 시간 초과로 처리(72행).
- 비밀: 없음.

비치명 메모:
- 62행 “3명이면 2라운드”는 1:1 예외 승인을 전제 — 예외 불수용 시 3명 게임은 1라운드로 끝남. 사용자 결정 필요(known_issues에 있음).
- 09-4절 “실제 참가자 3명 미만”을 생존자 기준으로 볼지 방 인원 기준으로 볼지 해석 차이 — 탈락자는 방에 남아 있으므로 규약 적용 대상 명시 필요.
- 방향 반전 직후 다음 차례가 이탈자로 빠지는 경우의 다음 사람 계산은 “순서에서 뺀다”로 해석 가능하나 테스트 케이스로 확인.

## REV v0.1 — 판정: pass
치명 문제: 없음.
- 종료: 문제당 최대 20초, 8문제 고정. 이탈자 제외한 활성 참가자 기준 “전원 정답”(68행).
- 비밀: 각자 제출은 본인만, 정답 채팅은 차단. 정답 자체는 공개 문구의 결정적 변환이라 시스템이 숨기는 비밀이 아님.
- 3명 성립, 입력은 전용 입력칸 + 채팅 — 플랫폼 가능.

비치명 메모:
- 스포 차단 “🤐”가 채팅으로 정답 여부를 알려 주는 오라클이 됨 → 오답 2초 잠김 없이 후보를 시험 가능. 채팅 차단 응답을 일반 “전송 실패”와 구분 안 되게 하거나, 차단 메시지도 제출로 판정하는 방식 검토.
- 회문 문제에서 원문 포함 채팅이 차단되므로 “회문이다”라는 힌트가 차단 응답으로 드러날 수 있음(30행 “알려 주지 않는다”와 긴장) — 위 항목과 같은 처리.
- “나가다오나나오다가나” 등 회문 목록 실제 회문 여부 콘텐츠 검수 필요.
