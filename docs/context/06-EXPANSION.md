# 6. 확장 가능성

아래는 보존할 비전이며 현재 MVP 구현 목록이 아니다. 재미 검증 뒤 근거에 따라 우선순위를 정한다.

| 축 | 보존할 방향 | 착수 판단에 필요한 근거 |
|---|---|---|
| 웹 플랫폼 | Roblox를 쓰지 않는 사람도 링크로 참여; 다양한 포맷 편성 | 채팅 게임 완료·재플레이·초대 |
| 아바타 / 코디 | 아바타 생성, 자기표현, 코디 상품 | 반복 이용과 정체성 수요 |
| 조작 방식 | 게임에 따라 채팅·투표·아바타 이동/행동으로 확장 | 텍스트 제약 때문에 잃는 재미의 증거 |
| 소셜네트워크 | 게임으로 친해지고 다시 모임; 친구·파티·최근 함께 논 사람 | 같은 사람과 다시 놀고 싶은 행동 |
| Roblox 병행 | AI 중간 개입 없는 게임 중심; 인원별 풀과 라운드 편성 | 웹과 독립된 실행 타당성·테스트 |
| 포맷 라이브러리 | 검증된 룰·변형·실험 결과를 플랫폼 간 재사용 | 여러 게임에서 재현되는 재미 장치 |

## 웹과 Roblox
웹은 채팅·비밀정보·관계 추리와 선택적 AI 제작진에 강점을 둔다. Roblox는 아바타 행동·이동·공간 상호작용으로 포맷을 변형할 수 있다. 웹 전용 사용자를 Roblox로 강제 유도하지 않는다.

병행은 가능한 전략이지 두 버전을 당장 동시 개발한다는 결정이 아니다. 공통 코드보다 포맷 ID, 핵심 규칙, 검증 결과를 먼저 공유한다. 플랫폼별 입력·타이밍·제약·사용자층이 달라 같은 QA 승인을 복사하지 않는다. Roblox용 별도 repo, 일정, 인원 상한은 미정이다.

## 쌓을 자산
게임 이름이나 생성 개수가 아니라 다음 묶음을 자산으로 남긴다.
- 핵심 재미 장치와 필요한 공개/비공개 정보 구조.
- 인원·관계·길이·AI 수준별로 검증된 변형.
- 상태 전이, 판정, 종료, Reveal, 재플레이 변주.
- 실제 실패 사례와 수정 결과; 폐기한 이유.
- 웹/Roblox 등 플랫폼별 변형과 재사용 가능한 규칙 부품.

TV 예능·파티게임은 기획 참고 대상으로 삼되 서비스명과 콘텐츠는 자체 설계하는 방향으로 정리한다. 구체적인 브랜드 사용 여부는 별도 결정한다.

최종 지향은 함께 놀고 친해지는 포맷을 축적하는 것이다. 코디 판매·경제 시스템·모바일 앱·소셜 피드는 재미가 확인되기 전 우선 구현할 이유가 되지 않는다.
