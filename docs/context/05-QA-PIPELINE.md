# 5. ASTRA → FABLE → 실제 사람 리뷰

확정된 순서는 ASTRA → FABLE → 실제 사람이다. 아래 역할 분담은 원대화의 제안을 실행 절차로 정리한 운영 규약이다. ASTRA/FABLE의 정확한 모델·도구·프롬프트·자동 실행 환경은 미정이다.

| 단계 | 입력 | 주 검토 대상 | 출력 / 다음 단계 조건 |
|---|---|---|---|
| ASTRA | 버전 고정 스펙, 분류, 상태/정보/판정 규칙 | 논리·시스템 | 재현 가능한 문제, 수정 제안, 통과/보류/폐기 |
| FABLE | ASTRA 통과 스펙과 리뷰 | 재미 가설·사회적 흐름 | 예상 재미/소외/Reveal 문제, 테스트 가설, 통과/보류/폐기 |
| 사람 | 수정 반영된 플레이 가능 빌드와 동일 버전 스펙 | 실제 이해·행동·재미 | 관측 기록, 남은 문제, 유지/수정/폐기 판단 |

## ASTRA 체크
승패·종료·동률·무응답이 정의되어 있는가. 무한 루프와 막힌 상태가 없는가. 한 사람만 할 일이 없는가. 비밀정보가 잘못 노출되는가. 미션이 동시에 성립 불가능한가. 악용 가능한 점수·제출 구조인가. AI 판정의 입력·기준·실패 동작이 명확한가. 이탈·재접속·최소/최대·짝수 제약에서도 성립하는가.

## FABLE 체크
룰을 짧게 설명할 수 있는가. 첫 행동을 쉽게 시작하는가. 웃음/추리를 만드는 장치가 있는가. 낯선 사람·친구 각각에서 성립하는가. 한 명만 유리하거나 표적이 되는가. 정적 구간이 긴가. 마지막 공개가 충분한가. 정체를 알고 재플레이해도 가능한가.

FABLE의 “재미있음”은 가설이다. 사용자 발언이나 사람 테스트 결과로 꾸며 기록하지 않는다.

## 사람 테스트
추가 설명이 필요한 지점, 첫 웃음까지 걸린 시간(관찰 가능할 때), 채팅이 멎은 구간, 참가자별 참여, 불쾌/소외, 종료 여부, 실제 재플레이와 초대/공유 반응을 기록한다. 말로 “재미있다”와 실제 “한 판 더”를 구분한다.

min=3인 게임은 실제 3명 테스트가 필요하다. 다른 인원과 관계 조건도 확인된 범위만 승인한다. both는 strangers와 friends를 각각 확인한다. 모든 인원을 시험하지 않았다면 미검증 범위를 공개 로비에서 지원하는 것으로 표시하지 않는다.

## 배치 운영
여러 게임을 한 배치로 ASTRA/FABLE에 보낼 수 있다. 탈락은 정상 결과다. 사람 테스트는 위험도와 잠재력이 높은 후보부터 순서를 정하되 **실제 출시할 모든 게임에는 사람 리뷰 근거가 필요하다**. 일부 표본 테스트를 전체 후보 승인으로 확대하지 않는다.

스펙 검토 후 구현하고 사람 테스트로 이어간다. FABLE 수정이 논리·상태·판정에 영향을 주면 ASTRA로 되돌린다. 사람 테스트에서 룰을 바꾸면 영향받는 단계부터 재검수한다.

각 리뷰는 게임 ID/버전, 구현 버전(있을 때), 검토자, 일자, 시나리오, 발견 문제, 근거, 판정, 다음 조치를 남긴다. 치명적 종료/정보 누출/참여 불가 문제는 해결 전 승인하지 않는다. 정량 합격선은 미정이며, Claude가 기록 없는 통과 상태를 만들면 안 된다.

공통 엔진 버그는 엔진 이슈와 영향 게임을 연결한다. 게임팩은 라운드 순서·총시간·피로·결과에서 다음 게임까지의 흐름을 별도로 테스트한다.
