# 5. QA — ASTRA(치명 문제) → 사람 테스트

**2026-09-29 개정 (DEC-13):** 종이 스펙을 반복 리뷰하느라 사람 테스트가 늦어지지 않게 절차를 줄였다. 스펙 단계에서는 **치명 문제만** 막고, 나머지는 구현·테스트에서 잡는다. 재미는 AI 예측이 아니라 사람 테스트로 확인한다.

| 단계 | 필수 | 입력 | 보는 것 | 통과 조건 |
|---|---|---|---|---|
| ASTRA | 필수 | 버전 고정 스펙, 09-ENGINE-RULES | 치명 문제 | **치명 0건** |
| FABLE | 선택 | ASTRA 통과 스펙 | 재미 가설·사회적 흐름 | 사용자가 필요할 때만 실행 |
| 사람 | 필수 | 플레이 가능한 빌드 또는 단톡방 수동 진행 | 실제 이해·행동·재미 | 유지 / 수정 / 폐기 판단 |

## ASTRA — 치명 문제만
치명 문제는 세 가지뿐이다.
1. **종료 불가:** 게임이나 라운드가 끝나지 않거나, 진행이 막히는 상태.
2. **비밀 정보 누출:** 공개 전에 시스템이 비밀(단어, 금지어, 투표자 등)을 알려주는 경로.
3. **참여 불가:** 규칙상 누군가 아무것도 할 수 없거나, 최소 인원에서 규칙이 성립하지 않는 경우.

- 치명 0건이면 `astra_passed`. 재리뷰는 하지 않는다.
- 치명이 아닌 지적(시간 경계, 중복 요청, 정규화, 동시 처리 순서, 밸런스 등)은 [구현 백로그](catalog/IMPLEMENTATION-BACKLOG.md)로 넘기고 구현·테스트 때 처리한다. 스펙을 고칠 필요가 없다.
- 치명 문제를 고치면 **그 항목만** 확인한다. 전체 재리뷰는 하지 않는다.
- 리뷰는 Claude가 이 대화를 모르는 **별도 리뷰어(서브에이전트)**로 실행하고, 결과를 `reviews/`에 저장한다. 사용자가 외부 모델로 돌리고 싶으면 `templates/REVIEW-PROMPTS.md`를 쓴다.

## FABLE — 선택
룰을 짧게 설명할 수 있는가, 첫 행동을 쉽게 시작하는가, 웃음 장치, 표적·소외, 정적 구간, Reveal, 재플레이. 사람 테스트 전에 관찰 항목을 뽑고 싶을 때만 쓴다. FABLE의 “재미있음”은 가설이며 사람 테스트 결과로 꾸며 기록하지 않는다.

## 사람 테스트
- 방식: 프로토타입, 또는 단톡방에서 한 사람이 진행자(사회자·집계)를 대신하는 수동 테스트.
- 기록: 추가 설명이 필요한 지점, 첫 웃음까지 걸린 시간(관찰 가능할 때), 채팅이 멎은 구간, 참가자별 참여, 불쾌/소외, 종료 여부, 실제 재플레이·초대·공유 반응. 말로 “재미있다”와 실제 “한 판 더”를 구분한다.
- min=3인 게임은 실제 3명 테스트가 필요하다. 확인된 인원·관계 범위만 승인한다. both는 strangers와 friends를 각각 확인한다.
- **출시할 모든 게임에는 사람 테스트 근거가 필요하다.** 일부 표본 테스트를 전체 승인으로 확대하지 않는다.

## 기록 원칙
- 각 리뷰·테스트는 게임 ID/버전, 검토자, 일자, 발견 문제, 판정, 다음 조치를 남긴다.
- 사람 테스트에서 룰을 바꾸면 바뀐 부분에 치명 문제가 생기지 않았는지만 ASTRA로 확인한다.
- Claude는 기록 없는 통과 상태를 만들지 않는다.
- 공통 엔진 문제는 09-ENGINE-RULES와 구현 백로그에 연결한다. 게임팩은 순서·총시간·피로를 따로 테스트한다.
