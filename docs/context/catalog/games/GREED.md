## 한 줄 경험 / 차별점
전광판: **“혼자 먹으면 대박, 둘이 먹으면 폭망!”** 매 라운드 40초 동안 채팅으로 “우리 다 나눔 하자~” 약속하고, 각자 몰래 🤝나눔 / 😈독식을 누른다. 발표 순간 **“배신자: 민수!”** — 약속을 믿은 사람들의 채팅이 폭발한다.
- 차별점: BATCH-01에 협상·배신 게임이 없다. 죄수의 딜레마를 한 판 4분·버튼 두 개로 줄였다. 마지막 라운드 점수 2배라는 불합리한 규칙이 막판 배신을 부른다.

## 플레이 규칙
- setup: 점수 0. 5라운드, 5라운드만 점수 2배(시작부터 공개).
- private_info: 각자의 선택은 마감 전까지 본인만 안다. 다른 사람에게는 “선택 완료 N/M” 숫자만.
- round_flow: 3·2·1 → **협상·선택 40초**(채팅 자유, 버튼은 마감 전 변경 가능) → 마감 → 발표 7초 → 다음 라운드.
- actions: 🤝나눔 / 😈독식 선택(변경 가능), 채팅(약속·협박·거짓말 자유).
- win_condition / scoring / ties:
  | 결과 | 점수 |
  |---|---|
  | 전원 나눔 | 전원 **+2** (“평화로운 밥상”) |
  | 독식 딱 1명 | 그 사람 **+(2 × 참가 인원)**, 나머지 0 (“배신 성공”) |
  | 독식 2명 이상 | 독식자 전원 **−2**, 나눔한 사람 **+1** (“욕심쟁이 폭사”, 착한 사람 위로금) |
  - 5라운드는 위 점수 **×2**.
  - 최종: 합계 순, 동률은 공동 순위.
- end_condition / timeout / no_response: 5라운드 뒤 종료. 마감 때 선택이 없으면 **나눔**으로 센다.
- reveal: 전원 선택 공개 → 전광판 “😈 배신자: 민수 +10!” 또는 “💥 욕심쟁이 폭사: 민수·지수 −2”. 최종 결과에 “배신왕”(독식을 가장 많이 누른 사람), “호구왕”(나눔만 5번) 타이틀 [제안].
- replay_variation: 사람마다 배신 성향이 드러나 다음 판 협상이 달라진다.

- ai_call_points / AI 사용 이유: 없음.
- judgment_criteria / deterministic_rules: 마감 시점 독식 수(0 / 1 / 2+)만으로 점수표 적용.
- ai_failure_fallback: 해당 없음.
- disconnect / reconnect / player_count_change: 아래 판정·처리 규약.
- failure_cases / exploit_cases:
  - 전원 계속 독식 → 매 라운드 폭사. 나눔한 사람만 +1이라 결국 나눔이 유리해지는 구조로 자연 해소 [가설].
  - 무응답 = 나눔이라 잠수한 사람이 “호구”가 됨 — 의도.
- social_risk / 소외 방지: 배신이 핵심이라 낯선 사이에서 불쾌감 가능 → 점수는 재미용, 결과 문구는 가볍게. 한 사람 몰아 배신하기는 구조상 불가(선택은 전원 동시).
- three_player_check: 3명이면 독식 1명 = +6, 2명 이상 폭사. 2명이 “둘 다 나눔, 쟤만 감시” 식 동맹·배신이 바로 생긴다. 역할·정보가 대칭이라 3명에서도 모든 결과가 가능하다. 테스트로 확인: 3명에서 매번 전원 독식(폭사)만 나오는지.
- 기타 인원 제약: 8명에서 독식 1명 성공 확률이 낮다 → 독식 1명 보상을 인원에 비례(2×인원)시켜 유혹을 유지.

## 판정·처리 규약 [기본값·가설]
[공통 판정 규약](../../09-ENGINE-RULES.md)을 따른다. GREED 고유 사항:
- **투표 마감:** `시작 ≤ 접수 < 시작+40초`. 마지막 유효 선택이 확정값. 마감 후 요청 무효.
- **동률:** 최종 합계 동률은 공동 순위. 라운드에는 동률 개념 없음.
- **이탈:** 마감 전 선택은 이탈 여부와 관계없이 집계. 선택 없이 이탈하면 나눔. “참가 인원”(독식 1명 보상 계산)은 라운드 시작 시점 인원으로 고정. 다음 라운드 전 3명 미만이면 누적 점수로 종료.
- **재접속:** 같은 라운드면 선택·점수 복원.
- **3명:** 위 점검 참고.
- **비밀 정보 전달:** 마감 전 view에는 본인 선택과 제출자 수만. 선택 결과는 결과 잠금 뒤 전원에게 동시에.
