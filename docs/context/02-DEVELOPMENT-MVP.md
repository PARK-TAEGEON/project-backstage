# 2. 개발 규칙 / MVP 원칙

## MVP 경계
기본 경험: 링크 또는 방 코드 → 닉네임 → 로비 / Ready → 채팅 게임 → 추리·투표(필요 시) → Reveal → 결과 → Play Again.

채팅 중심 웹으로 검증한다. 최소 3명으로 성립하는 포맷을 지원 대상으로 둔다. 모든 게임이 반드시 3명에서 동작해야 한다는 뜻은 아니다. 낯선 사람용 분류가 있다는 이유로 공개 매칭까지 MVP에 포함하지 않는다.

원대화 초기 후보는 Secret Director와 Everybody Knows Except You다. 둘 다 구현·채택 확정이 아니다. 후속 대화에서 여러 미니게임 실험으로 범위가 넓어졌으므로 첫 배치 수와 순서는 별도 결정한다.

MVP 제외: 아바타·이동·가상 공간·코디·아이템·친구/피드·클럽·복잡한 계정·랭킹·경제·과금·네이티브 앱·음성/영상·여러 AI 캐릭터·복잡한 메타게임.

## 개발 방향
- 방, 참가자, 세션, 게임 정의, 개인 지시, 이벤트, 메시지, 투표, 결과를 구분한다.
- 비밀정보 배포 / 타이머 / 채팅 / 개인목표 / 투표 / 공개 / 점수 등 반복되는 부품만 공통화한다.
- 게임별 규칙·상태 전이·프롬프트·판정·결과는 분리한다. 범용 엔진을 먼저 완성하려 하지 않는다.
- 모바일 브라우저에서도 입장하고 플레이할 수 있게 한다. 불필요한 로그인 단계를 줄인다.
- Next.js / TypeScript / Tailwind / Supabase는 인계 프롬프트의 추천안이다. 실제 repo의 선택을 확인하기 전 변경하거나 확정으로 기록하지 않는다.
- LLM 공급자는 얇은 교체 계층을 두고 프롬프트와 구조화된 입출력을 관리한다. 공급자·모델은 별도 결정한다.
- 매 채팅마다 LLM을 호출하지 않는다. 생성·필요한 판정·중간 사건·마지막 편집 등 목적 있는 호출만 설계한다.
- 규칙으로 확정할 수 있는 판정은 코드로 처리한다. AI 실패·지연·형식 오류 때의 종료/대체 동작을 게임 스펙에 적는다.

## 구현 시 적용할 운영 규약
- 공개 상태와 비밀 상태를 구분하고, 다른 참가자의 비밀이 Reveal 전에 전달되지 않도록 검증한다.
- 상태 전이·마감·중복 제출·점수의 기준을 하나로 정한다. AI 출력이 임의로 룰을 바꾸지 못하게 한다.
- API 키는 서버에서 관리하고 실제 secret을 commit하지 않는다.
- 정상 플레이 외에 이탈·재접속·침묵·동률·AI 실패·최소 인원 경계를 확인한다.
- 테스트 결과 없이 완료로 기록하지 않는다. 문서 상태와 코드 상태가 다르면 차이를 남긴다.

## 관측과 완료 기준
최소 관측: 시작, 완료, 중도 이탈, 재플레이, 초대, 결과 공유. 공유 기능 자체는 MVP 필수로 자동 승격하지 않는다.
재플레이율은 완료 세션 중 다시 시작한 세션 비율처럼 분모를 명시한다. 첫 웃음·채팅이 멎은 구간·소외는 사람 관찰로 기록한다. 목표 수치와 로그 보관 정책은 미정이다.

Claude는 작업마다 목적·범위·완료 기준을 쓰고 구현 결과를 검토한다. 종료 시 현재 상태, 결정, 검증 근거와 다음 작업을 갱신한다.
